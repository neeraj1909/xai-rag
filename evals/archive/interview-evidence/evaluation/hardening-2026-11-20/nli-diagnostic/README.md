# Frozen bilingual NLI contrast probe

Purpose: compare the currently configured NLI model and one pinned multilingual model on exactly the same **author-labeled synthetic** premise/claim pairs. This is a diagnostic sample, not a human review, representative benchmark, calibrated safety estimate, or reproduction of the H26 generated claim (which was not captured). H26/H27 use actual fictional source texts but reconstructed claims. Hinglish cases are a tiny stress slice, not evidence of supported performance. Labels are hypotheses and require independent adjudication.

Run only after the active evaluation releases its CPU/memory lease. Do not alter source, weights or the active pipeline. Record the fixture SHA-256, code revision/hash, model IDs and immutable revisions, tokenizer, Python/dependency versions, label map, truncation, duration, exceptions, RSS and per-pair raw scores; process models sequentially. Use offline mode if the models are pre-cached; otherwise request a separate bounded download and monitor disk/RAM. Use 0.5 unchanged for parity with current deployed threshold; do not tune and report a threshold on this same fixture. A separate adjudicated development set is needed for calibration and a disjoint holdout for final comparisons.

- Current: `MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli`, revision `6f5cf0a2b59cabb106aca4c287eed12e357e90eb`; model card labels it English.
- Candidate: `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`, revision `8adb042d524ecd5c26d3e3ba0e3fbcf7e2d0864c`, MIT. Its card reports XNLI 77.1% Hindi, 88.3% English; those are author-reported dataset classification accuracies, not this project's faithfulness performance. Approximately 279M parameters before activations; FP32 parameter storage alone is roughly 1.04 GiB, excluding tokenizer, runtime, copies and OS overhead. Confirm actual model download size, available RAM and runtime in a dry-run before downloading. See <https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli>.
- Lower-cost alternative for later comparison: MIT `MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli`, author card's XNLI Hindi 69.1%, English 78.9%; 0.1B params. These scores are not directly measured on our task. See <https://huggingface.co/MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli>.

Each model receives identical bounded pairs and the same label mapping. Report confusion counts separately for Hindi, Romanized Hindi and English; pay particular attention to **unsupported/contradictory false accepts** and supported false rejects. If the model's label mapping or required files are missing, fail closed and record the error rather than dropping the row. Report each model run's failures in denominator. Including a few spelling variants, sensitive negations and numbers is useful; add disjoint human-checked, production-representative examples before deciding any model swap. A candidate improvement on these 30 examples is not sufficient for deployment.

Routing should not rely only on query language: retrieved evidence and generated claims may use different languages or scripts and code-switch within a sentence. Start with the same multilingual model for a shadow comparison on all languages; if routing is considered later, evaluate query/claim/evidence language combinations, detector uncertainty and fallback. No routing path may bypass the independent judge, authorization or failure-closed behavior. Both local NLI and the remote judge can be wrong; changing NLI alone does not establish grounding.

The real HTTP evaluation's LLM verifier is a separate paid API call with additional latency and sends the prompt-visible evidence to the configured provider. This offline pair probe has no API cost. Record those system-level tradeoffs and provider data handling if later testing end to end.

# Synthetic HTTP, security and RAGAS evidence

Read the [experiment summary](../../../evaluation-hardening-evidence.md#current-application-http-and-ragas-evaluations) for scores, denominators, failures and interpretation. The datasets are fictional and author-labelled; there is no independent human review. A model judge from the same family as the generator is not independent proof of safety or answer correctness.

- `fixtures/holdout-cases.json`: the 40-question quality fixture, SHA-256 `b666492a41e218d6fefa0fcca0fa6ab26277bfb7dfba34413ffadb672afdc8cf`.
- `fixtures/cases.jsonl`: 28 security and utility cases, SHA-256 `851007eca4123773a57a4003378dbf8d85c82784fd81376d5b26f341a7a7cc3e`. Its accompanying original README describes the rubric and pre-execution state; the execution results are in `run/`.
- `first-attempt/`: initial 400 failures from an incompatible `max_tokens` parameter, corrected diagnostic, source manifest and the original shared provider ledger. The initial run stopped after three failed cases; do not omit it. The ledger continues through the subsequent successful HTTP run and original capped RAGAS pass.
- `run/`: per-case HTTP output, instrumented prompt-visible evidence, security model judgements, summary, manifest and the original partial RAGAS results (15 computed, one cap error, 24 unscored).
- `extension/`: separately budgeted RAGAS follow-up, per-case and combined evaluator results, manifest and its independent 300-attempt ledger. The original partial result remains in `run/`.
- `harness/`: the original scripts and report, preserved for auditing. These scripts contain original `/tmp` paths and may overwrite output, create or delete disposable resources, and incur charges. They are **not portable commands** and must not be run in place. Review and adapt an independent copy with new ports, directories, credentials, budgets and cleanup checks. The source may have changed since the scripts ran.

The test manifest records HEAD `c375903fb46327744d076438cb90f7b02711a94f` with uncommitted changes, Python source-tree SHA-256 `6e3c87bd0f650459d490c4f0d2c975f11ee18ce47686284f70014c374dbe9abd`. The harness did not preserve a source snapshot at run time; a later [reconstructed Python source snapshot](../evaluated-python-source/README.md) matches the recorded digest. It contains Python source only, not the full deployment or dependencies, so HEAD alone cannot reproduce these exact results. The `.env`, temporary API keys, policy files and application logs were intentionally excluded. A best-effort common secret-pattern scan and comparison against known temporary keys found no matches in selected artifacts; this is not a complete privacy audit. All documents and prompts in this experiment were fictional.

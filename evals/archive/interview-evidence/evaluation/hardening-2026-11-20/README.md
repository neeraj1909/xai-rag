# Evidence archive: hardening investigations, 20 November 2026

These materials describe separate synthetic experiments. For interpretation, denominators and limitations read [the evidence summary](../../evaluation-hardening-evidence.md); they do not establish production reliability or independent human review.

- `load/` contains the baseline report, aggregate summary, per-request/resource events and the original machine-specific runner. The runner used an ephemeral application key and a deterministic generation stub. The original source archive was not copied here; its SHA-256 and the published commit are recorded in the report. The 100-document synthetic fixture was generated by that runner; inspect its exact procedure before attempting comparison.
- `judge/` contains the frozen synthetic fixture, per-case results, raw provider responses and the original scripts. The fixture here has SHA-256 `c7efa755984497cf9f47a5cc9d7f660187e0e391951cdb47330b434ba0b227ce`. The preserved report refers to `../fixture.json` because of its original temporary location; the identical fixture is `judge/fixture.json` in this archive. Results came from a model alias, not a pinned dated snapshot.
- `revised-python-source/` contains the Python-only source tree matching the later REST/SSE candidate run; it is not a full deployment archive.
- `safety-full-candidate/` contains the later, 10-case REST/SSE candidate run; it uses a separate dirty-source digest and adaptive labels.
- `current-live-smoke/` records a separate one-scenario real-store/live-OpenAI smoke on a newer dirty source digest; it is not the earlier 40/28 aggregate.
- `final-e2e/` records the later stub-provider positive local E2E, authentication checks, prior failures, manifest and cleanup; the image was an overlay, not a clean Dockerfile build.
- `nli-literal-e2e/` preserves a separate local stub E2E false refusal on a verbatim cited claim and its one-example NLI context probe.
- `nli-diagnostic/`, `judge-question-candidate/`, `coverage-judge/` and `safety-coverage/` contain separate small synthetic diagnostics; their labels mix entailment with relevance and safety in places. No human validation is claimed. Coverage failed-auth attempt rows retain only case, status, error type and timing, with no credentials. The earlier question-aware prompt candidate was rejected.
- `evaluated-python-source/` contains a later reconstructed Python-only snapshot matching the HTTP manifest digest; it is not a complete deployment archive.
- `http/` contains the later synthetic end-to-end HTTP, security and RAGAS runs, the initial request-shape failure, partial capped run and separate completion; see [its evidence index](http/README.md).
- `transport-boundary/` contains a separate loopback stub comparison of pooled and connection-close HTTP requests; it does not identify the historical soak failures.
- `recovery-final/` contains the later real-store crash/replay repeat on final development source after the fsync fix, with per-file source hashes and cleanup records.
- `recovery/` contains the dated investigation, run metadata, health and cleanup evidence, and selected crash/recovery logs, including two failed attempts. The report begins with its earlier prototype state and later records integration and the passing test; do not mistake the earlier prototype section for the final status. Full Elasticsearch container logs are intentionally not copied; the high-level failure and cleanup records are retained.

**Historical scripts are evidence, not portable reproduction commands.** They include original absolute paths, output locations, expected temporary worktrees or disposable-container assumptions, and some may overwrite output or incur provider charges. Do not run them in place. To reproduce, make an independent copy, review and change every input, output, credential, port and cleanup path, and record all changes. See [local reproduction](../../local-reproduction.md) for the supported current walkthrough.

Before copying, selected text files were scanned for common OpenAI/GitHub token and private-key patterns, and key-related source references were inspected; this is a best-effort scan, not a guarantee that arbitrary logs contain no sensitive information. The tested prompts and documents were fictional. Original files and hashes were not edited to manufacture results.
